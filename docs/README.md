# OctoAcme Project Management Docs

This folder contains the complete OctoAcme project management framework, designed to help teams run projects with clarity, consistency, and customer focus.

## Overview

OctoAcme is a lightweight, principles-driven approach to project management that emphasizes:

- **Customer-first delivery**: Prioritize customer value and usability
- **Iterative progress**: Deliver small, testable increments frequently
- **Clear ownership**: Defined roles and accountability across teams
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Foster feedback, learning, and continuous improvement

The framework spans the complete project lifecycle—from validating business needs through initiation, planning, execution, release, and retrospective learning.

## Quick Start

**New to OctoAcme?** Start here:

1. Read the [Project Management Overview](octoacme-project-management-overview.md) for a quick intro to roles, principles, and the project lifecycle
2. Browse the guides below to find what you need for your project phase

## Project Lifecycle Guides

Follow these guides as you move through each phase of your project:

- **[Project Initiation](octoacme-project-initiation.md)** — Validate business need, align stakeholders, and authorize work
  - Problem statement → One-pager → Go/No-go decision
  
- **[Project Planning](octoacme-project-planning.md)** — Break work into shippable increments, identify dependencies, and create a delivery plan
  - Backlog creation → Estimates → Release plan
  
- **[Execution & Tracking](octoacme-execution-and-tracking.md)** — Manage day-to-day delivery, monitor progress, and resolve blockers
  - Standups → Sprint workflow → Blocker escalation
  
- **[Release & Deployment](octoacme-release-and-deployment.md)** — Standardize how features reach production with confidence
  - Pre-release checklist → Deployment → Rollback playbook
  
- **[Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)** — Capture learnings and convert them into actionable improvements
  - What went well → Improvements → Action items

## Cross-Cutting Guides

These guides apply throughout the project lifecycle:

- **[Risk Management & Communication](octoacme-risks-and-communication.md)** — Identify, track, and communicate risks; maintain stakeholder alignment
  - Risk register → Escalation paths → Status templates → Incident response
  
- **[Roles & Personas](octoacme-roles-and-personas.md)** — Understand key responsibilities and communication patterns
  - Project Managers, Product Managers, Developers, QA/Testing, and other team members

## How to Use These Docs

- **Getting started on a project**: Create a project repository or workspace. Use the [Project Management Overview](octoacme-project-management-overview.md) as your reference, and follow the phase-specific guides in order.

- **Working within a phase**: Pick the relevant guide above and follow the checklists, templates, and workflows.

- **Handling risks or escalations**: Refer to [Risk Management & Communication](octoacme-risks-and-communication.md) for escalation paths, templates, and communication playbooks.

- **Understanding team roles**: Check [Roles & Personas](octoacme-roles-and-personas.md) to clarify responsibilities and typical communication patterns.

- **Grounding Copilot Spaces**: Add process-specific docs to `.copilot/` if you want Copilot Spaces to use them as context for your project. This lets Copilot provide guidance tailored to your team's processes.

## Key Artifacts

Throughout your project, you'll create and maintain:

- **Project Charter / One-pager**: Problem, goal, success metrics, stakeholders, timeline
- **Roadmap and Release Plan**: Milestones and delivery schedule
- **Sprint/Iteration Backlog**: Prioritized list of work with acceptance criteria
- **Risk Register**: Identified risks, impact, mitigation, and status
- **Retrospective Notes**: Learnings and action items for improvement

## Communication Cadence

- **Weekly sync** between PM and Product Manager
- **Twice-weekly standups** for delivery team (or as agreed)
- **Monthly stakeholder updates** on progress and risks
- **Ad-hoc escalations** as needed for blockers and issues
